# RED/GREEN 재현 하네스 — 스택별 레시피

## 원리 (스택 무관)

같은 실패 시나리오를 **두 번** 돌린다: 미수정 코드(RED)와 최소 수정본(GREEN). 두 번 다 *실제 출력*을 캡처한다. 하네스는 그걸 재현 가능·격리하게 돌릴 수 있는 가장 가벼운 것이면 된다. 핵심은 도구가 아니라 **실제 사용 경로를 그대로 태우는 것**.

규칙:
- **실제 경로**를 태워라. 합성 단축(내부 메서드 직접 호출)은 "실사용에서 도달 가능한가" 를 못 증명한다.
- **수정을 빼도 RED 가 뜨는지** 반드시 확인 — 안 뜨면 재현이 가짜다(hollow).
- **상태를 변경하는 재현**(DB write·파일 생성·동시성)은 변형별로 격리하거나 직렬화. 읽기 관찰은 공유 가능.
- 한 클론에서 gradle/npm/git 를 동시에 돌리지 마라(stale-artifact 레이스).
- **워크트리를 갈라도 빌드는 직렬로.** 워크트리는 소스만 가르고 `~/.m2`·`~/.gradle` 같은 로컬 리포는 공유한다.

## 가짜 RED 세 가지

RED 는 **컴파일되고 단언이 실패**해야 한다.

| 형태 | 증상 | 처방 |
|---|---|---|
| 컴파일 에러 RED | 수정이 시그니처를 바꿔서, 되돌린 코드에 새 테스트가 안 붙는다 | 테스트가 **양쪽 형태를 다 받게** 짠다(리플렉션으로 메서드 탐색 등) |
| 엉뚱한 줄 치환 | 스크립트가 같은 문자열을 가진 **주석 줄**을 먼저 잡아 실코드는 그대로 | 줄 단위로 앵커를 잡고, 토글 후 실제 diff 를 눈으로 본다 |
| 층이 어긋난 테스트 | 저장 계층을 단언하는데 수정은 컨트롤러 가드 — 수정해도 RED 가 안 풀린다 | 테스트를 **수정과 같은 층**에서 다시 쓴다 |

되돌리기에 `git stash` 를 쓰면 **이미 커밋한 파일은 잡히지 않는데도 명령은 성공**한다. 빈 stash 위에서 통과한 것을 GREEN 으로 읽지 마라. 특정 파일만 원본으로 보려면 `git show origin/<base>:<파일> > <파일>`.

**임시 변조는 되돌릴 때 `touch` 까지.** 바이트코드·빌드 캐시가 mtime 을 보므로, 내용만 복원하면 변조본이 계속 로드된다.

## 웹앱 (서버 + DB)

일회용 DB 에 앱을 올리고, 정확한 사용자 경로를 HTTP 로 구동(로그인 + 폼 전송), **DB 행 델타 + 응답 + 서버 로그**를 캡처한다. 미수정/수정본을 두 포트로 같은 DB 에 나란히 띄우거나, DB 를 리셋하며 순차로.

- 관찰 지표: 응답 바이트·HTTP 상태·에러 로그·SQL 쿼리 카운트(ORM 로그)·영향받은 행 수.
- 로그인·CSRF·필수 입력 검증에서 막힌 것을 "차단됐다" 로 오독하기 쉽다. 내 수정이 동작한 게 아니라 그 앞에서 죽은 것일 수 있다 — **후속 요청이 200 인지, DB 행이 실제로 바뀌었는지**로 본다.
- 샌드박스에서만 바꾼 설정(쿠키 secure 플래그, `skipTests` 등)은 커밋 대상이 아니다. 반드시 원복한다.

**증명은 3점이다.** 수정 전 실패 재현 → 수정 후 해소 → **정상 사용자는 여전히 성공**. 세 번째가 없으면 과잉 수정 지적을 받는다. 각 점을 응답이 아니라 **DB 행 실측**으로 찍어라.

**접근제어를 조사할 땐 하네스가 유일한 판정자다.** 정적 읽기로 "검사가 없다" 가 나와도, 요청을 실제로 태워 302/401 이 아닌 **핸들러 실행**을 확인하기 전엔 결론이 아니다. 상위 필터·설정이 도달 자체를 막을 수 있다.

## 클라이언트 라이브러리 (JS/TS/Kotlin/…)

변형별로 클론/워크트리를 격리한다. 실제 API 경로를 태우는 **실패하는 테스트**를 쓰고, 라이브 API 또는 fixture 로 돌린다. 수정을 빼면 RED 가 뜨는지 확인.

- **fixture > 라이브 드리프트**: 라이브 의존·서브모듈이 오래돼 드리프트가 있으면, 의존을 올려 드리프트를 깨우지 말고 **캡처한 실제 응답을 fixture 로 박아** 직접 검증한다.
- dist/빌드 산출물을 커밋하는 저장소면 소스와 함께 산출물도 갱신한다.

## CLI / 순수 함수

트리거 입력을 먹여 잘못된 출력(RED) → 올바른 출력(GREEN)을 단언하는 일회성 스크립트나 유닛 테스트. 가장 가벼운 형태.

## 체크

- [ ] 실제 사용 경로를 태웠다(합성 아님)
- [ ] RED 에 real output 이 있다(숫자 요약 아님)
- [ ] 수정을 빼면 RED 가 재현된다
- [ ] 변형 간 상태 격리/직렬화됐다
